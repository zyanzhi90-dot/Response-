# Reviewer Response 知识库设计纲领

## 一、最终目标


- 以江 TIE_2621 为写作范例，使新的审稿回复在**整体结构、内容顺序、段落推进、句间衔接、单句表达和具体用词**上都保持一致的写作习惯，最终达到“像同一作者写的”效果。

## 二、基础原则与知识库边界

2. **分清不同材料的作用**
   审稿意见、论文、实验结果和作者思路决定**回答什么、事实是什么、结论能说到哪里**；TIE 范例决定**这些内容怎么组织、怎么推进、怎么表达**。知识库负责把范例中稳定、可迁移的规律提炼出来，用于新的审稿意见。

3. **所有对齐都按层级进行**
   对每个 Comment 的 Response，按照：
   **整条回复 → 各个部分 → 每一段 → 连续句子 → 单句话和具体用词**
   逐层检查。
   每一层都先搞清楚**这一层整体想完成什么**，再研究**具体怎么实现**。只有所有层级都与范例对齐，整条回复才能真正对齐。

4. **知识库只保存能够迁移到新问题的规律**
   当前某个审稿意见可以暴露知识库缺口，但具体任务、变量、实验、某一句修改方法只作为验证材料。最终留下的应当是换一个 Comment 仍然成立的规律，避免知识库逐渐变成当前项目的修改记录。

## 三、Response 的组织与表达层面

5. **先判断当前审稿意见，再安排整条回复**
   先搞清楚审稿人真正提出了什么问题、其核心关切和当前情况是什么，再据此判断整个 Response 应该回答哪些核心问题、分成几个部分、各部分承担什么作用、按照什么顺序出现。
   开头通常简短感谢，随后尽快进入核心回答、修改或结果；第一段应让审稿人较快抓住重点。复杂问题根据实际内容展开，不预设固定段数、篇幅或结构。

6. **再逐个部分从整体看到局部**
   对每一个部分，先明确**这一部分整体想表达什么、为什么放在这里、与前后部分是什么关系**。
   然后再继续往下看它由哪些段落组成、每段承担什么作用。新的部分要自然进入；需要明确说明目的时可以使用类似 `To...` 的写法，上下文已经清楚时直接进入内容。

7. **每一段都要先搞清楚“这一段在干什么”**
   不能一上来就改句子。先确定这一段是在回答、解释、比较、补充实验、说明结果、报告修改，还是进行其他实质推进。
   再找到 TIE 中**作用相近的段落或场景**，研究范例在这种情况下从第一句到最后一句是怎么写的。

8. **对照范例时要从头到尾逐句检查**
   对一段或一个连续内容，不能只挑几句看。要从第一句开始顺着检查：
   **第一句怎么进入 → 第二句为什么这样接 → 后面怎样展开 → 什么时候转折或补充 → 怎样进入结果或修改 → 到哪里自然结束。**
   重点看整段的推进方式，而不是把几句分别正确的话拼在一起。

9. **单句话和具体用词也必须对齐**
   继续检查每句话的**主语、核心动词、句式、信息顺序、限定条件、连接方式、句长、术语重复、语气和具体用词**。
   整体保持朴素、直接、专业、自然。一般性的“学术英语润色”不能代替范例作者真实的表达习惯，范例自身明显不自然或不严谨的地方也不照搬。

10. **一些写作惯例要学会“什么时候用”**
    第一声感谢怎么写、第一段怎么进入重点、什么时候需要 `To...` 说明目的、什么时候直接进入内容、什么时候需要结果后的结论、什么时候给出修改位置，这些都有范例中的使用规律。
    知识库要学习这些规律和适用条件，不能把某一种写法固定成所有 Response 都执行的模板。

## 四、实验图表与最终成文层面

11. **实验、结果和图表也按同样的层级学习**
    先看这一组实验或图表在整条回复中承担什么作用，再看这一部分如何组织，然后逐段、逐句研究范例怎样进入实验、交代必要信息、引出图表、读取结果以及是否继续得出结论。
    多张相关图围绕同一个问题组织，公共内容集中说明，避免每张图重复一整套过程。

12. **内部可以分析得很细，最终回复保持最小充分**
    为保证正确性，内部可以详细分析问题、关系、范围和风险。最终写给审稿人的内容只保留帮助其理解回答、判断结果和核查修改真正需要的信息。
    内部分析的细致程度不能直接变成最终回复的复杂程度。

## 五、知识库迭代与最终验收层面

13. **真实失败要反过来检查知识库**
    每次回复出现问题，都要判断遗漏发生在哪一层：**整条回复、部分安排、段落功能、句间推进、单句表达、具体用词，还是实验图表等特殊内容**。
    如果说明某一层的规律没有学全，或虽然写进知识库但还不够清楚、难以执行，就回到 TIE 原文继续补强这一层。已经解决的内容保持稳定，不反复重做。

14. **最终验收也按照同一层级从整体到局部进行**
    先看整条 Response 是否正确回答了当前审稿意见，再逐个部分、逐段、逐个连续句子，最后逐句逐词检查。
    每一层都先判断**它是否正确承担了当前 Response 中应有的作用**，再判断**其具体组织、推进和表达是否与 TIE 中作用相近的场景对齐**。只处理真正影响达标的问题，达到标准后直接通过。

## 整套知识库设计的核心思路

**每个 Comment 的 Response 都要先搞清楚审稿人真正提出了什么问题，再按层级从整体到局部逐层对齐。先看整条 Response 应该怎样组织，分成几个部分，每一部分整体要表达什么、怎么推进。再逐个部分从整体看到局部；到了具体段落，先搞清楚这一段想表达什么、承担什么作用，再调用知识库中已经从 TIE 提炼并验证的、与该功能相对应的组织与表达规律，从第一句开始逐句检查结构、衔接、句式和用词。只有整条回复、部分、段落、连续句子和单句等每一层都分别对齐，最终才能真正形成稳定的同作者写作风格。**
