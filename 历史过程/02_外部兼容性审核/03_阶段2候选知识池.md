# 阶段 2 候选知识池

> 本池汇总经阶段 2 外部兼容性审核后仍保留的候选。共 23 条：阶段 1 候选 20 条，外部补充候选 3 条。它们尚不是最终知识库规则；`VALIDATED` 也只表示机制与本轮外部成熟原则兼容。

## A. 经审核保留的阶段 1 候选

### CK-001

- **Function:** 让 reviewer 在回复开头尽快看到直接答案、已完成动作或新增证据。
- **Evidence:** TIE R1-2/R3-2/R4-3 与 A1/A2/A3 用户验收；NR-STANCE/NR-STRUCTURE；ARS-REVISION/ARS-REBUTTAL。
- **Observed pattern:** 简短致谢后迅速进入 action、comparison 或 evidence，而不以空泛元话语替代回应实质。
- **Boundary:** 不要求固定开场、被动语态或禁用 `clarify`；若需澄清，须立即给出被澄清内容或实际改动。
- **Positive example:** 当前项目由元话语式开头改为直接报告 comparisons 已完成（仅作 illustration）。
- **Negative / rejected example:** 把 `We wish to clarify ...` 当作 TIE 惯用模板。
- **Provenance:** 阶段 1 CK-001；Nature 与 ARS 外部兼容性审核。
- **Validation status:** `VALIDATED_WITH_BOUNDARY`

### CK-002

- **Function:** 将被点名的局部缺陷转化为有边界的同类问题审计，而非零散补丁。
- **Evidence:** A1/A2/A3 的真实纠正；NS-CONSISTENCY、NR-PACKAGE；ARS-REBUTTAL/ARS-REVISION。
- **Observed pattern:** 从具体错误提取可定义的问题类别，回查受影响范围，同时保持已正确且已验收的内容不动。
- **Boundary:** “同类”必须有证据化定义；不得借机引入新风格偏好、无限扩大审计范围或重开已通过内容。
- **Positive example:** 用户点名一个多先行项语境中的模糊代词后，检查同类语境（仅作 illustration）。
- **Negative / rejected example:** 只改点名短语便宣布整体达到 TIE 水平，或反过来借一次点名重写全篇。
- **Provenance:** 阶段 1 CK-002；Nature consistency/package QA；ARS coverage QA。
- **Validation status:** `VALIDATED_WITH_BOUNDARY`

### CK-003

- **Function:** 保证每个 reviewer concern 都由直接相关的证据回答。
- **Evidence:** TIE R4-4 反例与三源用户裁决；NR-TAXONOMY/NR-ACTION/NR-QA；ARS-ARGUMENT/ARS-CLAIMREF。
- **Observed pattern:** 先确定 concern 的判断标准，再核对实验、指标与结论是否真正回答该标准。
- **Boundary:** 可使用多类证据，但必须说明每类证据分别回答什么；相邻或代理 evidence 不自动等价。
- **Positive example:** 当前项目将 convergence 与 computational efficiency 分别交给相应指标回答（仅作 illustration）。
- **Negative / rejected example:** 用 network size 或 tracking error 充当另一方法的 runtime evidence。
- **Provenance:** 阶段 1 CK-003；Nature concern—action—evidence；ARS claim–evidence alignment。
- **Validation status:** `VALIDATED`

### CK-004

- **Function:** 当 reviewer 混合不同概念、指标或尺度时，建立理解 concern 所需的最小评价框架。
- **Evidence:** A1/A2/A3 的概念区分裁决；NR-TAXONOMY/NR-ACTION；ARS-REVISION/ARS-CLAIMREF。
- **Observed pattern:** 将复合判断拆成独立维度，说明每个维度回答什么，再分别配置 evidence 和 conclusion。
- **Boundary:** 只拆 reviewer 实际混合的维度；框架须来自 comment、稿件定义或 primary evidence，不扩写成教程或自创评价体系。
- **Positive example:** 当前项目区分跨迭代收敛与每步实时判据（仅作 illustration）。
- **Negative / rejected example:** 由迭代轮次减少直接推出每步计算时间更低。
- **Provenance:** 阶段 1 CK-004；Nature compound-concern mapping；ARS atomic subclaim review。
- **Validation status:** `VALIDATED_WITH_BOUNDARY`

### CK-005

- **Function:** 将服务同一子问题的多项实验组织成紧凑、可核验的证据单元。
- **Evidence:** TIE R1-2/R3-2/R4-3；A2 evidence-block 重组与用户验收；A3 复核。外部资料仅提供相容的“最短充分证据链”，未直接命名该机制。
- **Observed pattern:** 集中说明共同目的/公共条件，连续呈现相关图组和关键现象，以一次有限结论收束。
- **Boundary:** block 数量和边界由 concern—evidence 关系决定；不要求所有 response 使用固定 block 数或固定内部模板。
- **Positive example:** 当前项目把同一子问题下的相关实验分别聚为两个功能性 block（仅作 illustration）。
- **Negative / rejected example:** 每张图重复 purpose → setup → result → mini-conclusion，末尾再重复总结。
- **Provenance:** 阶段 1 CK-005；TIE 原生组织证据；Nature/ARS 仅作不冲突核验。
- **Validation status:** `TIE_NATIVE_KEEP`

### CK-006

- **Function:** 在压缩重复信息时保护区分实验和支撑结论所需的独有证据。
- **Evidence:** A2/A3 用户裁决；NS-MAINTEXT/NS-CONSISTENCY；ARS-REBUTTAL/ARS-ARGUMENT。
- **Observed pattern:** 公共目的和设置只说一次，各实验不可替代的条件、结果和相关不利比较仍保留。
- **Boundary:** 公共/独有信息按具体 experiment 和 claim 判定，不预设通用参数清单。
- **Positive example:** 当前项目集中公共平台/周期，同时保留各 Case 的独有条件与结果（仅作 illustration）。
- **Negative / rejected example:** 因“设置已说明一次”而删除 case-specific result 或 variation condition。
- **Provenance:** 阶段 1 CK-006；Nature main-text discipline；ARS evidence sufficiency。
- **Validation status:** `VALIDATED`

### CK-007

- **Function:** 让 claim 与支持它的 evidence 在 reviewer 阅读路径上保持低跳转、可追踪的邻近关系。
- **Evidence:** TIE 图表组织与 A1/A2/A3 用户验收；NR-STRUCTURE/NR-ACTION/NR-PACKAGE；ARS-CLAIMREF。
- **Observed pattern:** 通过紧邻排版、明确 cross-reference 或稳定 location mapping，使论点、图表和读图结论可直接互查。
- **Boundary:** “相邻”是功能目标，不是像素级规则；具体实现受期刊版式和材料类型约束，reviewer-specific 扫读假设不可泛化。
- **Positive example:** 当前项目把判据、关键结果和有界结论置于正式图附近（仅作 illustration）。
- **Negative / rejected example:** 远处集中堆图，只在正文留下无法快速定位的悬空图号。
- **Provenance:** 阶段 1 CK-007；Nature traceability/package consistency；ARS source anchoring。
- **Validation status:** `VALIDATED_WITH_BOUNDARY`

### CK-008

- **Function:** 让实验进入句先说明证据为何存在、对应哪个 concern 或 criterion。
- **Evidence:** TIE R1-2/R3-2 与三源用户裁决；NR-STRUCTURE/NR-ACTION；ARS-REVISION/ARS-ARGUMENT。
- **Observed pattern:** 先显化实验目的或比较对象，再立即给必要设置和 evidence；流程词只在确有顺序关系时使用。
- **Boundary:** 不固定使用 `To further...`，也不要求每个 figure 重复 purpose sentence。
- **Positive example:** 当前项目用目的性进入说明后续比较用于评估哪一判据（仅作 illustration）。
- **Negative / rejected example:** `Next, we vary ...` / `Finally, we vary ...` 只报告操作次序。
- **Provenance:** 阶段 1 CK-008；Nature action mapping；ARS commitment/evidence alignment。
- **Validation status:** `VALIDATED`

### CK-009

- **Function:** 分配 caption 与正文的互补职责，使图可识别而正文保持高信息密度。
- **Evidence:** TIE 图文组织与三源用户裁决；NS-MAINTEXT、NR-PACKAGE；ARS-CLAIMREF 仅作 evidence-anchor 辅助。
- **Observed pattern:** caption 提供识别图所需的对象、条件、指标、panel 与必要参考；正文读取 concern-relevant 现象、解释和边界。
- **Boundary:** 自足程度由期刊规范和 figure complexity 决定；不推出所有 caption 都须重复 citation、数值或正文解释。
- **Positive example:** 当前项目由 caption 说明 panel/判据识别信息，正文只提炼关键结果与结论（仅作 illustration）。
- **Negative / rejected example:** 为压缩正文而删掉 caption 的必要条件，或让正文逐字重复 caption。
- **Provenance:** 阶段 1 CK-009；Nature main-text/caption discipline；外部 QA 补边界。
- **Validation status:** `VALIDATED_WITH_BOUNDARY`

### CK-010

- **Function:** 降低模糊指代、图号和 panel 引用造成的 reviewer 回读与误配成本。
- **Evidence:** A1/A2/A3 的真实指代纠正与 TIE 多图引用；NR-ACTION/NR-PACKAGE/NR-QA；ARS-REVISION/ARS-CLAIMREF。
- **Observed pattern:** 多个候选先行项并列时显化方法、指标、任务或 figure；唯一先行项时允许自然指代。
- **Boundary:** 以实际歧义风险为触发条件，不禁止代词，也不要求每句重复全称或完整 Fig. 编号。
- **Positive example:** 当前项目在两张图并列时写明各自对应 panel（仅作 illustration）。
- **Negative / rejected example:** 前文含多张 figures 时只写 `Panels (d) show...`，未指明对应关系。
- **Provenance:** 阶段 1 CK-010；Nature/ARS traceability 对照。
- **Validation status:** `VALIDATED_WITH_BOUNDARY`

### CK-011

- **Function:** 使 response 的结论范围严格匹配实际测试和证据覆盖范围。
- **Evidence:** 三源用户裁决、正式 primary evidence 与 TIE 过强 claim 反例；NR-ACTION/NR-TONE/NR-QA；ARS-ARGUMENT/ARS-CLAIMREF。
- **Observed pattern:** 保留 tested/reported 条件，不从有限比较推出所有任务、平台或普遍保证。
- **Boundary:** 限定语应准确而不防御性堆叠；不是每句都需重复全部条件。
- **Positive example:** 当前项目将结论限定在已测试任务和已报告 variations（仅作 illustration）。
- **Negative / rejected example:** 使用 `universally`、`guarantee` 或无证据的“最低计算成本”断言。
- **Provenance:** 阶段 1 CK-011；Nature claim-softening/status discipline；ARS claim–source alignment。
- **Validation status:** `VALIDATED`

### CK-012

- **Function:** 对与 concern 和结论有关的不利结果保持透明，并据此校准 claim。
- **Evidence:** 三源一致裁决与正式图事实；NS-MAINTEXT、NR-TONE/NR-QA；ARS-CLAIMREF。
- **Observed pattern:** 报告 material adverse result，说明它与目标判据的关系，再把结论收束到仍被支持的范围。
- **Boundary:** 只要求保留实质影响当前 concern、比较或 claim 的不利证据，不罗列所有无关负面观察。
- **Positive example:** 当前项目同时报告某方法较 comparator 慢、但仍满足目标判据（仅作 illustration）。
- **Negative / rejected example:** 删除不利 timing，只保留有利 task cost 来暗示全面优势。
- **Provenance:** 阶段 1 CK-012；Nature conclusion-changing evidence rule；ARS partial-support audit。
- **Validation status:** `VALIDATED_WITH_BOUNDARY`

### CK-013

- **Function:** 限定不同来源的证据职责，维持可追踪的裁决链。
- **Evidence:** A1/A2/A3 来源索引、自审及用户归并原则；NR-SOURCE/NR-WORKFLOW/NR-QA；ARS-CITATION/ARS-CLAIMREF。
- **Observed pattern:** 范例原文支持范例机制，用户裁决支持项目采用，稿件/正式图支持定义与结果，派生总结只辅助定位。
- **Boundary:** 来源矩阵随项目变化；不要求所有项目使用相同材料类型，也不把多个派生文件重复计为独立证据。
- **Positive example:** 当前项目以本稿稿件定义纠正本稿符号，而不让外部范例替本稿命名（仅作 illustration）。
- **Negative / rejected example:** 用总结者补写句冒充 benchmark 原句，或用代码图注反推正式结果。
- **Provenance:** 阶段 1 CK-013；Nature source hierarchy；ARS provenance/faithfulness audit。
- **Validation status:** `VALIDATED`

### CK-014

- **Function:** 建立稳定、可核验的指标、术语与符号语言。
- **Evidence:** 三源中的真实更名/符号纠错链；NS-CONSISTENCY、NR-PACKAGE；ARS-REVISION/ARS-CLAIMREF。
- **Observed pattern:** reviewer 首次需要理解时给出完整含义和符号，随后稳定使用；修改后同步 response、稿件、图表和 caption。
- **Boundary:** 不要求每次重复定义；定义位置和正式名称由当前稿件/实验 primary source 决定，外部 Skill 无命名权。
- **Positive example:** 当前项目首次给出完整 metric name 与 symbol，后文稳定用 symbol（仅作 illustration）。
- **Negative / rejected example:** 同一指标在多个近义名称/符号间漂移，或从文件名创造变量。
- **Provenance:** 阶段 1 CK-014；Nature consistency/package audit；ARS traceability 辅助。
- **Validation status:** `VALIDATED_WITH_BOUNDARY`

### CK-015

- **Function:** 在证据链末端给出一次清晰、正面、有边界且不重复的结论。
- **Evidence:** TIE 的一次性收束与三源用户裁决；NR-TONE/NR-STRUCTURE、ARS-ARGUMENT 仅提供相容原则，未直接规定该段落节奏。
- **Observed pattern:** 从已陈述 evidence 推出有限 conclusion，不重新枚举全部图值，也不在尾句引入新的防御术语。
- **Boundary:** reviewer 明确要求 limitation、风险或未完成项时，必要说明不能为了简洁而删除。
- **Positive example:** 当前项目以已建立 criterion 和 tested conditions 一次收束（仅作 illustration）。
- **Negative / rejected example:** 在末尾新增免责声明式句子，重复防御并引入未经定义的新术语。
- **Provenance:** 阶段 1 CK-015；TIE 原生组织证据；Nature/ARS 仅作兼容性核验。
- **Validation status:** `TIE_NATIVE_KEEP`

### CK-016

- **Function:** 控制 response 中实现细节的相关性和信息密度。
- **Evidence:** 三源中的真实删除裁决；NS-MAINTEXT、NR-TONE；ARS-ARGUMENT/ARS-REBUTTAL。
- **Observed pattern:** 保留 reviewer 判断所需的对象、指标、条件、结果和结论；其余细节留在适当位置或删除。
- **Boundary:** 若 concern 涉及 reproducibility、implementation、measurement protocol 或 fair comparison，实现细节就是核心 evidence，不得按类型删除。
- **Positive example:** 当前项目只保留 timing metric、比较关系和判据所需信息（仅作 illustration）。
- **Negative / rejected example:** 详细描述计时代码或网络规模，却未回答 computational-efficiency criterion。
- **Provenance:** 阶段 1 CK-016；Nature information-placement discipline；ARS relevance audit。
- **Validation status:** `VALIDATED_WITH_BOUNDARY`

### CK-017

- **Function:** 使对论证必要的外部方法和来源在 reviewer 可核查的位置可追踪。
- **Evidence:** 三源中的真实漏引纠正；NR-WORKFLOW/NR-QA/NR-DIFFICULT；ARS-CITATION/ARS-CLAIMREF。
- **Observed pattern:** 外部方法首次需要识别、比较或承担 evidence role 时建立来源关系；后续是否重复按语境判断。
- **Boundary:** 不是每个 method name 都自动需要新 citation；citation style、编号、首次位置和 caption 重复由项目与期刊决定。
- **Positive example:** 当前项目在外部 comparison method 首次承担论证作用时给出可解析来源（仅作 illustration）。
- **Negative / rejected example:** 只写外部方法名或 manuscript 编号而无可核查来源，或猜测缺失 citation 编号。
- **Provenance:** 阶段 1 CK-017；Nature citation verification；ARS citation/source alignment。
- **Validation status:** `VALIDATED_WITH_BOUNDARY`

### CK-018

- **Function:** 从高水平范例迁移 reviewer-response 机制，同时隔离范例自身缺陷和偶然特征。
- **Evidence:** TIE 原文中的有效组织与真实语言/claim 缺陷；三源“不照搬”裁决；NR-SOURCE；ARS-STYLE。
- **Observed pattern:** 提取段落动作、证据位置、图组推进、信息密度和收束功能，不复制句子、错误、平台或参数。
- **Boundary:** 单一范例只形成待验证观察；迁移前须区分功能、venue convention 和原文缺陷，并保留 provenance。
- **Positive example:** 迁移 action → evidence → reading → bounded conclusion 的功能节奏（仅作 illustration）。
- **Negative / rejected example:** 照抄 TIE 原文中的拼写/语法错误、过强 claim 或项目参数。
- **Provenance:** 阶段 1 CK-018；Nature source-boundary 原则；ARS soft style calibration。
- **Validation status:** `VALIDATED_WITH_BOUNDARY`

### CK-019

- **Function:** 为“达到目标水平”和“停止继续改写”建立范围明确、可验证的完成门槛。
- **Evidence:** A1 过早完成错误、A2 用户验收、A3 停止泛化润色裁决；NR-ACTION/NR-QA/NR-PACKAGE；ARS-REBUTTAL。
- **Observed pattern:** 分开记录 response action、work status 与 package readiness；在约定范围通过后，只因新 evidence、明确 defect 或新 request 重开相关检查。
- **Boundary:** style acceptance、事实核验、build、visual QA、citation numbering 和 submission readiness 是不同状态；后续局部修改只重开受影响链条，不自动授权全篇改写。
- **Positive example:** 当前项目在整体内容/逻辑/表达通过后仅做点名修改（仅作 illustration）。
- **Negative / rejected example:** 修几处短语即宣布达到 TIE 水平，或写作通过后继续凭一般偏好重写正确段落。
- **Provenance:** 阶段 1 CK-019；Nature status/readiness separation；ARS advisory-audit boundary。
- **Validation status:** `VALIDATED_WITH_BOUNDARY`

### CK-020

- **Function:** 使 response 的篇幅、段数和图量服从 concern 的证据需求。
- **Evidence:** TIE 中简单与复杂回应的长度差异及三源裁决；NR-TONE/NR-STRUCTURE/NS-MAINTEXT；ARS-REBUTTAL。
- **Observed pattern:** 简单修正可短，复杂比较可长；规模以完整、可核验的 evidence chain 为准，而非外观模仿。
- **Boundary:** 不设固定字数、段数或图数；完整性、期刊要求和 concern 严重程度优先于机械压缩。
- **Positive example:** 当前项目把重复 mini-responses 压为较少 evidence blocks，同时保留必要结果（仅作 illustration）。
- **Negative / rejected example:** 因 benchmark 某回复图多篇幅长，便增加无关图或解释以模仿外观。
- **Provenance:** 阶段 1 CK-020；Nature concise-but-sufficient；ARS coverage/evidence-risk QA。
- **Validation status:** `VALIDATED_WITH_BOUNDARY`

## B. 外部补充候选

### ESC-001

- **Function:** 忠实保存 reviewer intent，把复合 comment 拆成可追踪的原子 concern/commitment，并防止静默漏项。
- **Evidence:** NR-TAXONOMY/NR-WORKFLOW/NR-QA；ARS-REVISION/ARS-REBUTTAL。
- **Observed pattern:** 原始 comment 保留；内部 concern inventory 逐项映射 action、evidence 与 status；未解决项显式保留。
- **Boundary:** 只拆 reviewer 实际提出的独立判断点，不为每个修饰语制造任务；外部回复的段落数量可按可读性合并。
- **Positive example:** 一个 comment 同时要求解释和新增验证时，内部记录为两个 commitment，再在一份连贯回复中分别闭合（外部原则 illustration）。
- **Negative / rejected example:** 只回答复合 comment 中最易处理的一部分，却把整条标记为完成。
- **Provenance:** Nature direct response workflow；ARS revision/rebuttal audit；阶段 1 CK 未覆盖的新增候选。
- **Validation status:** `EXTERNAL_SUPPLEMENT_CANDIDATE`

### ESC-002

- **Function:** 将 reviewer 对已有信息的漏读或误解视为清晰度/可见性信号，并形成直接回答与 presentation revision。
- **Evidence:** NR-STANCE/NR-WORKFLOW/NR-DIFFICULT/NR-TONE。
- **Observed pattern:** 不责备 reviewer；直接回答 concern；必要时改善 wording、placement、signposting、legend 或 cross-reference。
- **Boundary:** 必须先由 primary source 证明信息确已存在；真实 evidence gap 不能伪装成“只是 reviewer 没看见”。
- **Positive example:** 说明原 presentation 未充分显化某点，并给出更清楚的位置或表述（Nature difficult-case illustration）。
- **Negative / rejected example:** 以 `this was already stated` 或“reviewer should have noticed”结束回应。
- **Provenance:** Nature difficult-case 原则；阶段 1 CK 未覆盖的新增候选。
- **Validation status:** `EXTERNAL_SUPPLEMENT_CANDIDATE`

### ESC-003

- **Function:** 在互盲 review 中隔离 reviewer-specific 信息，同时对重复或冲突 concern 分别给出独立完整回应。
- **Evidence:** NR-ENTRY/NR-STRUCTURE/NR-QA/NR-DIFFICULT。
- **Observed pattern:** 重复/冲突只在 internal/editor master 中关联；每位 reviewer 面前都独立说明同一科学决定，不跨引其他 reviewer。
- **Boundary:** 只在 reports 或回复互相不可见时适用；若 editor/journal 明确要求综合或公开答复，应遵从其规则。隔离不意味着科学结论可以互相矛盾。
- **Positive example:** 同一 concern 被两位 reviewer 提出时，两份 reviewer-facing response 各自完整说明统一的 manuscript action（Nature difficult-case illustration）。
- **Negative / rejected example:** 写 `as noted in our response to Reviewer 1`，或透露另一 reviewer 的 comment/建议。
- **Provenance:** Nature reviewer-isolation 原则；阶段 1 CK 未覆盖的新增候选。
- **Validation status:** `EXTERNAL_SUPPLEMENT_CANDIDATE`

## 池边界

- 本池不包含阶段 1 的 `CASE_SPECIFIC`、`SOURCE_FACT_ONLY`、`REJECTED`、`SUPERSEDED` 或 `UNRESOLVED` 项。
- 当前项目的术语、变量、数值、图号、citation 编号和版本状态只在标明的 illustration 中出现，不构成候选命题。
- 本池未把 Nature/ARS 的固定 phrase、模板、标点或论文级量化阈值纳入候选。
