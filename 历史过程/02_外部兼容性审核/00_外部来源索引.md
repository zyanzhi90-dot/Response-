## 3. 本轮采用的证据职责

- 直接 reviewer-response 原则用于检查：comment 是否被忠实解析、是否逐点回答、动作是否明确、证据是否可核验、语气是否非防御、状态是否准确。
- claim/source 辅助模块用于检查：claim 是否被证据完整支持、部分支持是否被误报为完全支持、来源是否越权、citation 或事实不确定性是否被显式保留。
- package/consistency 模块用于检查：response 与稿件、图表、caption、术语、定位和最新版本是否同步；它们不自行决定 TIE 风格。
- style 模块只支持“外部通用偏好不能覆盖 venue/benchmark 证据”的边界，不用于引入 phrasebank。

## 4. 明显不适用而未读取/未采用的模块

| 模块或原则 | 排除理由 |
|---|---|
| ARS deep-research、systematic review、experiment-agent、paper generation 等完整流水线 | 本轮不做文献检索、实验设计、论文生成或研究执行 |
| ARS reviewer simulation / manuscript peer review | 本轮审核的是已有知识候选，不模拟新的 reviewer report |
| Nature / ARS 的固定 phrasebank、模板句和标点偏好 | 可能是单一 venue 或写作偏好，不能替换 TIE 原文基准 |
| 论文层的量化阈值，如固定证据流数量、固定评分、固定引用比例 | 不属于 reviewer-response 的普适机制，且可能与具体 comment 不相干 |
| citation 格式、DOI 完整率、自引比例等投稿级规则 | 可作为其他阶段的文献合规任务，但不决定本轮候选的 response 机制 |
| 统计、伦理、合规的专门工作流 | 只有相应 reviewer concern 出现时才启用；当前 20 条 CK 不以这些专题为对象 |
