# 分层执行协议回归验收基线

## 0. 用途与边界

本文件只为下一阶段修改 `03_最终知识库` 的执行协议建立修改前基线和行为验收规格。它不参与默认 Response 生成，不新增 TIE 写作规律，也不裁决当前 C1/C2 的 Whole Response、Part 或 Paragraph 是否通过。

唯一最终目标仍是：在科学事实正确的前提下，使未来 Agent 按 **Reviewer 真实问题 → 有序核心判断 → 整条 Response → Part → Paragraph → 连续句 → 单句与具体用词** 从高到低工作，并在各层稳定实现江 TIE_2621 的组织、推进和表达习惯。

本轮待验证的是执行体系，而不是预先证明某种实现有效：

1. 分层、逐单元执行能否减少 one-shot 审计只抓显眼问题的漏检；
2. Reviewer argument 与 response alignment 分开处理，能否避免把 supporting premise 机械升级为独立 obligation；
3. 可恢复的 coverage state 能否证明实际遍历范围，并在版本变化后正确失效；
4. 同一 hierarchy 能否支持 Draft、Audit、Revise，同时不把简单 Comment 膨胀成模板；
5. phrase-level 检查能否同时核对语言实现和 scientific attachment，并用正确反例控制过检；
6. causal reopening 能否重开真正受影响的上游根因及其依赖项，而不无边界重做。

上述均为待测假设。回归通过只能说明在本文件规定的有限材料和条件下得到支持，不能推出“零漏检”“已达到同作者级”或“C1/C2 已全层级 PASS”。
