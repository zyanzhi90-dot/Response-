# 分层执行协议与中间产物

## 1. 定位与共同约束

本文件是 Draft（初稿）、Audit（只读验收）和 Revise（定点修改）共用的**执行顺序协议**。它规定每层的输入、内部产物、通过条件和返工关系；不新增 TIE 写作规律，不替代 `01`–`05`/`07` 的内容规则，也不改变 `00` 的来源权限。后续由 `06_Response生成与验收流程.md` 调度本协议；`08` 仍是历史验证记录，不充当现行通过证明。

一条 comment 的执行路径是：

**Reviewer understanding → Whole Response → Part → Paragraph → continuous sentences → sentence/phrase realization → integrated read-through**。

先确定并暂时冻结上一层的**意义与职责**，再进入下一层。冻结表示下层据此工作，不表示发现新的原始证据、覆盖缺口或逻辑冲突时不得重开。Draft 中，高层未成立就不写依赖它的英文；Audit 中，高层发现问题仍须记录其影响并继续完整检查指定文本，不能把未通过的高层当作下层 PASS 的前提。Part、Paragraph 和句子均无预设数量或固定形式。

各层的产物是简短、可回查的内部工作记录，可合并记在一份笔记或当前任务上下文中；**不要求新增文件、表格或对外标题**。它们只证明思路和检查过程已经完成，不是 reviewer-facing Response 的提纲，也不因记录齐全而自动证明科学正确。当前项目 primary evidence 决定事实、证据和 claim；作者明确确认且无冲突的 response plan 决定其确认范围内的科学主线和必要顺序；TIE PDF 是唯一组织与表达金标准。

## 2. 七层交接与进入条件

表中的“通过”只表示**允许进入下一层的内部工作门槛**。最终 Response 的 PASS 仍须满足 `06` 的 TIE-style 和 supporting audits；不能由一张内部规划表代替。

| 层级 | 输入 | 最小内部产物 | 进入下一层的条件 |
|---|---|---|---|
| **1. Reviewer understanding** | 原 comment 的完整论证；当前项目材料；作者明确确认的计划与其边界 | 关切记录：区分 supporting premise、reviewer 判断与真正的 response obligations；记下各义务所需事实或动作、证据状态及已确认的项目约束 | 不按技术命题句数拆义务；每项真正义务可指认，事实或计划冲突、未核实处保持可见；足以确定 reviewer 最终需要接受什么判断 |
| **2. Whole Response** | 第 1 层产物；可用证据、claim 边界；相关 TIE 组织机制 | **整体 blueprint**：直接回答、有序核心判断、判断间依赖、各判断所需证据与可支持范围，以及整条回复如何进入和完成 | 整条回答覆盖真正义务，顺序与作者已确认路线、理解依赖和证据相容；不存在靠低层措辞才能掩盖的主线空缺。冻结这一整体关系后再划 Part |
| **3. Part** | 已冻结的整体 blueprint | **完整 Part 结构图**：逐 Part 记整体职责、承接前一 Part 或开头已建立的信息、所负责判断与证据、向后一 Part 交接的实际问题；单 Part 也记录其整体职责 | 先看完整结构，再专注处理各 Part；所有必要判断有归属，前后承接可解释，没有只靠编号成立的块、职责重复或无依据的固定块数 |
| **4. Paragraph** | 全部 Part 的职责与交接；对应证据和图文任务 | **每个 Part 的完整段落图**：逐 Paragraph 记局部判断或推进任务、从上层/前段接收的信息、所需理由或 evidence、段尾完成什么或交给下段什么 | 先确定所有需要的段落及段间关系，再逐 Part、逐段执行；每段服务其 Part，必要证据有位置，段首和段尾的衔接不悬空；无需为短答硬造段落 |
| **5. Continuous sentences** | 当前段的任务、上一段交接和下一段需求 | 段内**语义推进线**：第一句要建立什么，后续每一步回应前一步留下的什么需求，末句完成本段还是向下段交接；只标功能与依赖，不预写固定句数或连接词 | 从第一步到末步可以连续顺读；条件、setup、推导、locator、observation、修改位置等仅在本段任务需要时出现；无跳步、空转或与 Part/段落职责冲突 |
| **6. Sentence/phrase realization** | 已确定的连续推进；当前项目 primary evidence；`02` 的语言实现与 `04` 的科学边界 | 对**目标文本全部句子**的覆盖记录：每句承担的功能和实际表达；对会改变含义的关键 phrase 同时核对语言与 object、condition、baseline、metric、modifier scope、evidence range、claim scope；记录未通过处及其所在层级 | 不凭语法自然或发现数个显著问题提前结束扫描。目标范围内每句均已检查，关键短语的科学附着可核验；局部问题和可能上溯的结构问题分别标记。Draft 需完成相应自检，Audit 须完整读完指定文本 |
| **7. Integrated read-through** | 全文及前六层产物、问题记录和当前证据状态 | 从头到尾的**交接核对与状态记录**：Whole→Part→Paragraph→句群→短语是否仍是一条回答链；跨段/跨图表的指代、证据、claim 和可查位置是否相容；标明已通过、未证实或须返工的范围 | 只有指定范围内的完整性、TIE 组织与表达、科学附着和必要 supporting gates 均无真实 blocker，才可报告 PASS；否则按根因层级返工或如实报告 FAIL。不能因局部读起来顺畅代替整条验收 |

Part 是实质职责单位，不必有编号或标题；Paragraph 是该 Part 内的局部推进单位。短回复可以只有一个实质 Part 或一段，仍按相同关系检查，不为填满层级而扩写。句群在段落与短语之间承担连续推进职责，不能由若干各自正确的孤立句子拼成。

## 3. 同一协议在三种模式中的用法

| 模式 | 各层的任务 | 冻结与输出 |
|---|---|---|
| **Draft** | 依次建立第 1–5 层的完整内部结构，先完成 Whole、全部 Part 与各 Part 的段落关系，再逐 Part、逐 Paragraph 写出并核对第 6 层；最后做第 7 层通读 | 每层通过后才下钻。若事实或证据不足，保留缺口，不用流畅英文替代。内部结构不机械外显到 Response |
| **Audit** | 从原 comment 和 primary evidence **独立重建**第 1–5 层期望，再与现有 Response 逐层比较；第 6 层逐句、逐关键短语覆盖整个指定文本；第 7 层检查跨层实际阅读效果 | 高层出现 blocker 时记录其受影响链条，后续检查注明依赖关系，不能把下层局部合格冒充整条 PASS；仍须完成全文句/短语发现。内部记录可包含非 blocker，最终报告才筛出真实 blocker |
| **Revise** | 先由 Audit 或明确反馈定位**最早失效层**，在该层重建必要产物，再沿依赖向下重做受影响的 Part、段、句群与短语；最后通读受影响边界和本轮指定目标 | 高层变动使其所依赖的低层旧通过状态失效；局部措辞问题不自动重开 Whole。修后只把实际重验范围标为通过，不把定点修订宣称为未经执行的全篇验收 |

“只报告 blocker”是 Audit 的**最终筛选与交付规则**，不是内部发现规则。第 6 层必须读完用户指定的全部目标文本；即使先发现 Whole 或 Part 的问题，也要继续识别独立的句/短语缺陷和受高层问题牵连的位置。非 blocker 可留在内部记录，不据此制造 FAIL 或扩张修改。

## 4. 返工与按需加载

发现问题时先确定其**根因层级**及受影响链条：Whole 改动重开相关 Part 以下；Part 改动重开该 Part 及其与相邻 Part 的交接；Paragraph 改动重开该段、必要的相邻段与句群；句/短语改动重开该句、必要的邻句和相关证据或交叉引用。低层核对若揭示 reviewer 理解、事实或 claim 边界原本有误，须上溯重开相应高层，再向下重验。返工范围由真实依赖决定，不按文件或篇幅机械扩大。任何修改后的 integrated read-through 都检查新的接缝。

按当前层的任务逐步披露材料，避免在每一步同时执行全库规则：

- **来源与关切入口：** 用 `00`/`06` 确定来源权限和任务状态；按 `01`、`04` 识别义务、判断标准与证据边界；仅当 `07` 的条件满足时调用相应 CS 单元。
- **整体、Part、Paragraph：** 主要用 `01` 的 TN-01/02/03/08 和已验证 A/B 机制；有实验、图或表时再用 `03`。C 类单例只供回查原 scene，不生成固定结构。
- **连续句与词句：** 由 `02` 选择与当前语义任务有关的 SL；关键 phrase **同时**调用 `04` 的 SD-01/SD-03 和项目证据。`05` 用于核对实际触发的错误机制，不作为逐句套用的另一套模板。
- **溯源与最终核对：** TIE PDF 是唯一风格原始金标准；`04_TIE句子级表达重建` 的 realization、scene 和 validation 只在机制适用性、边界或表达判断存疑时按需回查。`08` 只提供历史映射和状态，不能覆盖现行审计。

Nature Skills / Academic Research Suite 仅提供“短调度层、按需读取、可检查中间产物、阶段门槛和返工状态”这些知识工程启发；本协议的 Response 内容、适用边界和语言判断仍由当前项目证据、作者已确认计划及 TIE-derived 知识决定。各层产物始终留在内部，reviewer-facing Response 只呈现回答所需的最小充分内容。
