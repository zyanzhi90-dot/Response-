# 条件型补充规则

本文件只保存阶段 2 的 3 条 external supplements。它们管理特殊情形，不决定 TIE 的句法、段落节奏或 evidence block 写法。只有触发条件满足时才加载。

## CS-01 复合 comment 的原子 concern inventory

### 触发条件

一个 reviewer comment 同时包含两个或以上可独立判断完成与否的 response obligations，例如要求作者分别解释、证明、补证据或修正不同事项。comment 中用于支撑最终质疑的事实、比较和理由，不因数量多就触发本单元。

### 执行

1. 保留原 comment，不改变其 intent。
2. 先理解完整论证，再把真正需要分别回应的义务分开记录。某论据只有本身要求处理，或不处理便无法闭合最终质疑时，才成为核心回答链的一项。
3. 每项分别映射 action、direct evidence、claim boundary、修改位置和状态。
4. 起草时可为可读性合并成连贯段落或 evidence block，但不得静默漏项。
5. 未解决项保持可见，不能因其他部分回答充分就把整条标为完成。

### 不触发或停止条件

不要为每个修饰语、技术命题或论证前提制造任务，也不要把原子化机械执行成一句 comment 对应一个碎片段落。只拆 reviewer 实际提出的独立 response obligations；必要的前提仍可在相应回答中解释或核查。

### 与 TIE core 的关系

CS-01 只在写前确保覆盖；外部成文仍使用 TN-01 至 TN-08。TIE R4-4 是漏项风险的反例，但 CS-01 的完整 inventory 来自外部 supporting workflow。

**Provenance:** ESC-001。

## CS-02 已有信息被漏读或误解

### 触发条件

Primary source 能证明 reviewer 所需信息在送审稿中已经存在，但 reviewer 未看到、未理解或把其关系读错。

### 执行

1. 先直接回答科学问题。
2. 检查原 wording、placement、signposting、legend 或 cross-reference 是否足够清楚。
3. 必要时做最小 presentation revision，并给可核验位置。
4. 用 TIE core 组织回答，不把责任推给 reviewer。

### 禁止

- `This was already stated`、`as clearly described` 或 “reviewer should have noticed”。
- 把真实 evidence gap 伪装成漏读。
- 为已经清晰且无新缺陷的内容做无止境重写。

### 停止条件

若 primary source 不能证明信息确已存在，退出 CS-02，回到 SD-01 按 evidence gap 处理。

**Provenance:** ESC-002。

## CS-03 互盲 reviewer 隔离

### 触发条件

存在多位 reviewer，且报告或作者回复彼此不可见；除非 journal/editor 明确规定 combined/public response。

### 执行

1. 在 internal/editor master 中记录重复或冲突 concern。
2. 先形成全局一致的科学与稿件动作。
3. 为每位 reviewer 写独立、完整的 response，只包含该 reviewer 的 comment 和对应回答。
4. 重复 concern 在每份可见回复中完整回答，不跨引其他 reviewer。
5. 冲突 concern 在内部协调后，分别用各自 comment 和共同 manuscript evidence 解释，不泄露冲突来源。

### 禁止

- `as Reviewer 2 also noted`；
- `see our response to Reviewer 1`；
- 暴露另一 reviewer 的编号、recommendation、身份、comment 或 author response；
- 因隔离而给出互相矛盾的科学结论或稿件修改。

### 覆盖规则

若 editor/journal 明确要求综合答复或透明公开评论，服从该规则，并记录 visibility 边界。CS-03 不覆盖期刊指令。

**Provenance:** ESC-003。

## 条件层总边界

CS-01 至 CS-03 不应被包装成“所有 TIE responses 都这样写”。它们只在覆盖、清晰度或信息隔离风险出现时提供额外纪律；具体成文仍回到 TIE-native core。
