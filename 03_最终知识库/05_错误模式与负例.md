# 错误模式与负例

本文件保留阶段 1 已确认的 11 条历史 `REJECTED` 路径，并记录知识库后续实际使用中经核验的 failure。历史路径经 TIE PDF、用户裁决或 primary evidence 核实；其中的项目专有名词只用于说明原错误，不得迁移为新项目规则。

## E-01 把非原文句子当作 TIE 语言指纹

- **错误机制：** 派生总结或 Agent 补写的 `We wish to clarify...` / `The point we wish to clarify...` 被误报为 TIE 惯用开场。
- **为什么失败：** PDF 原文不支持；summary 无权冒充 primary source。
- **正确处理：** 迁移“感谢后尽快进入答案/动作”的功能。`clarify` 只有在立即给出实质内容时才可使用。
- **边界：** 不是在所有语境禁用该词串。
- **Provenance:** CI-021、EV-01。

## E-02 把直接否定当作默认开场

- **错误机制：** 用 `We do not claim...` 先防御，再迟后给真实目标和 evidence。
- **为什么失败：** 把注意力放在对抗和元话语上，容易重启 reviewer 的负面框架。
- **正确处理：** 先正面界定实际评价对象、已做动作和有限 evidence；必要否定只服务于边界。
- **边界：** 否定句并非绝对禁用；被否决的是其作为默认/TIE 式开场。
- **Provenance:** CI-022、EV-02。

## E-03 让一般 academic-writing 偏好覆盖 benchmark

- **错误机制：** 以“更专业、更规范、更完整”为由引入 TIE 未体现的固定句式、标点、版式或扩写。
- **为什么失败：** 风格判断失去原文证据，支持层越权。
- **正确处理：** 回到 TIE PDF 核对组织和表达功能；通用原则可以修正事实、证据、claim、source、一致性及真实的语法、搭配、命名和可读性缺陷，但不能代替 TIE 决定 Response 写法。
- **边界：** 准确、自然的英语仍必须纠正 TIE 原文自身错误。
- **Provenance:** CI-023、EV-03。

## E-04 用流程词替代真实语义推进

- **错误机制：** 用 `Next`、`Finally` 等只报操作顺序的流程词代替 evidence 与当前 concern 的实质关系。
- **为什么失败：** 当上下文尚未说明 evidence 的作用时，reviewer 只能看到操作先后，无法判断结果如何回答问题。
- **正确处理：** 让 action、setup、locator 和 observation 按实际认知需求推进；仅在 reviewer 无法从上下文理解 evidence 的作用时，补充最小的 purpose 或 criterion 说明。
- **边界：** 顺序本身有解释意义时可以使用流程词；evidence 的作用已经清楚时，不额外写 purpose。
- **Provenance:** CI-024、EV-05。

## E-05 模糊指代和悬空图号

- **错误机制：** 多个先行项或多张图并列时只写 `its`、`the criterion`、`those in the manuscript`、`panels (c)` 或孤立图号。
- **为什么失败：** evidence 可能被归错对象，reviewer 被迫回读。
- **正确处理：** 在实际歧义处写明方法、指标、任务或具体 figure/panel。
- **边界：** 不禁止自然代词，也不要求每句列完整 Fig. 编号。
- **Provenance:** CI-025、EV-10。

## E-06 对每个实验机械重复 purpose 模板

- **错误机制：** 每项实验或每张图都以相同 `To further...` 句型重新启动。
- **为什么失败：** 句子功能重复，证据主线被切碎，形成模板感。
- **正确处理：** 同一子问题的公共信息集中交代，各项 evidence 的独有条件和结果仍须保留；purpose 仅在确有解释作用时出现，不按 block 机械重复。
- **边界：** `To further...` 可作为一次自然的功能载体，不是禁语。
- **Provenance:** CI-026、EV-06。

## E-07 强制所有 caption 重复 citation

- **错误机制：** 为形式统一，要求外部方法在每个 caption 中重复文献编号。
- **为什么失败：** 把期刊/上下文依赖的 citation 决策变成机械格式规则，并增加重复。
- **正确处理：** 在方法首次承担识别或比较作用的位置建立可追踪来源；caption 是否重复按自足需求和期刊规范决定。
- **边界：** 某一 figure 内确需 citation 时可以保留，不能反推通则。
- **Provenance:** CI-027、EV-09。

## E-08 每张图各写完整 mini-response

- **错误机制：** 每幅图重复 purpose → setup → result → mini-conclusion，末尾再总述一次。
- **为什么失败：** 造成重复论证，公共设置多次出现，主线松散。
- **正确处理：** 按 concern—evidence 关系组成 evidence blocks，共同信息集中，独有 evidence 保留；是否需要 conclusion 由当前 concern 决定，若需要则由 TN-07 / SD-01 检查其必要性、非重复性和 evidence boundary。
- **边界：** 若两幅图回答不同 concern，应分开，而不是强行合并；不为每张图强制添加 conclusion。
- **Provenance:** CI-028、EV-07。

## E-09 用代理 evidence 或非授权来源替代直接 evidence

- **错误机制：** 用另一模型的网络规模、tracking error、相近实验、代码/脚本图注或派生总结替代 reviewer 真正要求的 runtime、延迟、量化等目标 evidence。
- **为什么失败：** evidence 与判断标准不对应；来源越权。
- **正确处理：** 为每个 concern 找直接 evidence，部分覆盖就明确部分状态；没有 evidence 就缩小 claim 或保留缺口。
- **边界：** 多类 evidence 可以组合，但必须说明各自回答什么。
- **Provenance:** CI-029、EV-15/20；TIE R4-4 为同类部分回应反例。

## E-10 隐藏不利结果或扩大 claim

- **错误机制：** 删除较慢或不占优的比较，只保留有利指标，并推出 `lowest`、`universal`、`guarantee` 等结论。
- **为什么失败：** 破坏证据诚实性，claim 超过测试范围，并可能重建 reviewer 已担忧的误解。
- **正确处理：** 报告与 concern 有关的不利 evidence，说明它与目标 criterion 的关系，并把结论限定在仍被支持的范围。
- **边界：** 不要求罗列与当前 concern 无关的所有负面观察。
- **Provenance:** CI-030、EV-18；当前 Comment 1 的具体比较只作历史 illustration。

## E-11 整体回退旧稿或堆叠新旧版本

- **错误机制：** 因旧稿某些版式或信息位置可取，便整体回退其语言，或把旧新两版叠加成更长回复。
- **为什么失败：** 失效术语、旧 claim 和低质量英语回流，重复与版本冲突增加。
- **正确处理：** 只逐项吸收仍有效的信息层级、图文位置或事实，再按当前来源和 TIE core 重写受影响部分。
- **边界：** 历史稿可作 provenance 和负例来源，不能作现行语言标准。
- **Provenance:** CI-031、EV-21。

## E-12 把内部分析过程机械外显到最终 Response

- **错误机制：** 把内部的 concern 拆解、evidence 分类、审计清单、规划步骤或推理过程按原样写进最终 Response。
- **为什么失败：** 内部工作用于保证判断正确；机械外显会重复已清楚的信息、延迟实质回答，并使 reviewer 承担无关的分析负担。
- **正确处理：** 内部分析可以充分展开。进入最终 Response 前，只保留回答当前 concern、理解必要科学逻辑或 evidence、判断或限定 conclusion、消除真实歧义、核查 evidence 或 manuscript revision 的具体位置，以及必要且简短的礼貌承接所需的信息；以最小充分形式表达。
- **边界：** 不因信息来自内部步骤而删除必要的科学解释、证据或限定；流程预告、分类结果和宽泛的“导航”不能单独成为保留理由。
- **Provenance:** 知识库后续使用中经确认的 failure；supporting QA，非 TIE-native fingerprint。

## E-13 把 reviewer 的论据机械升级为独立 concern

- **错误机制：** 按 comment 中技术事实、比较或推理的句数逐项造 response obligations，而不先读清它们共同支撑的最终质疑。
- **为什么失败：** 核心回答链被铺垫材料切碎；Part 和段落可能围绕 reviewer 并未独立要求的事项展开，真正的判断反而被延后或遗漏。
- **正确处理：** 先还原完整 argument，再识别必须分别闭合的 response obligations。论据只有本身要求处理，或不处理便无法闭合最终质疑时，才成为核心回答链的一项；否则在所属判断中按需解释。
- **边界：** 不得因此跳过错误的技术前提或 reviewer 明确提出的独立请求；是否需要处理仍由原 comment 与项目证据决定。
- **Provenance:** 后续实际使用中经确认的 reviewer-understanding failure；TIE R2-C2、R2-C3 与 R4-C4 的 comment/response 对照仅支持区分论证功能及覆盖边界，不提供固定分类模板。

## E-14 首次定义后让 reviewer-facing prose 长期裸写符号

- **错误机制：** 首次定义关键量后，跨段落或证据块仍连续使用裸符号、公式或不等式承担 criterion、结果和结论，使技术含义只存在于较早的定义处。
- **为什么失败：** reviewer 必须回查并解码才能判断当前句的对象；术语虽然一致，阅读中的判断链仍会断开。
- **正确处理：** 首次给技术名称与正式符号；在新的段落/证据块及关键判断位置按需要就近重现含义与符号，局部连续推导可只用符号。
- **边界：** 不要求每次重复全称或把公式改成文字；只在实际阅读负担出现的位置补足语义。
- **Provenance:** 后续实际使用中经确认的可读性 failure；TIE 跨 scene 的技术名词连续复现支持实现方式，具体符号取自当前项目。

## E-15 逐句验收只看英语而漏查科学附着

- **错误机制：** 某个条件、方式、范围或比较短语语法成立、读起来自然，就直接给 sentence-level PASS，没有核对它实际修饰的对象及其证据范围。
- **为什么失败：** 一两个词即可改变实验层级、baseline、metric 或 claim scope；整体 evidence gate 通过也不能保证该句没有重新定义科学关系。
- **正确处理：** 每个关键 phrase 同时过 `02` 的语言实现与 `04` 的 SD-01/SD-03：查实际对象、条件、baseline、metric、modifier scope、evidence range 和 claim scope，再决定该句是否 PASS。
- **边界：** 对不会改变科学含义的普通措辞不制造逐词负担；TIE 句式不能替代新项目 primary evidence 的事实核对。
- **Provenance:** 后续实际使用中经确认的 phrase-level audit failure；现有 A4 的条件/baseline 邻接及 SD-01 claim gate 提供调用边界，非新增 TIE 文风规则。

## E-16 用一般英语可接受性替代同功能 TIE realization 判断

- **错误机制：** 逐句覆盖后，只确认原句语法正确、意思可恢复或读起来自然，便给 Sentence/Phrase PASS；没有脱离原措辞重建 meaning，也没有独立形成同功能 TIE shadow realization 并比较真实差异。
- **为什么失败：** 这种检查会漏掉仍可理解、却在功能承载、对象命名、主语与核心动词、信息组织、符号可读性或连续推进上偏离 TIE 的表达。
- **正确处理：** 按 `02 §4`、`06 §5.2` 完成 meaning reconstruction → shadow realization → differential comparison；只报告由当前语境和同功能 TIE 证据支持的实际偏离。
- **边界：** shadow 措辞不同不自动构成问题；不把当前任务的词组或 TIE 原句做成禁词表、模板，也不以风格判断替代 primary evidence 的事实核对。

## E-17 Obligation 闭合后继续添加无必要的防御性说明

- **错误机制：** 当前 obligation、必要解释、evidence、claim boundary 和 traceability 已闭合，下一句也没有新的必要认知职责，却为了显得完整或保险继续添加 defensive / insurance statement。
- **为什么失败：** 额外句子把内部顾虑带入 reviewer-facing Response，稀释已经完成的判断并增加无关阅读负担。
- **正确处理：** 按 `06 §5.2` 的 necessity gate 在闭合处停止；若下一句确有新的必要职责，保留并检查其证据和承接。
- **边界：** 不能由 TIE 范例的表面停止位置推出当前任务已经充分回答；必须先核对当前 obligation 和证据是否闭合。

## 防止错误回流的使用法

发现某个负例时，只修复其对应机制，并检查证据化定义下的同类位置。不得从一个错误扩展为全篇无边界润色；修复后按 SD-04 的受影响链条复核并停止。
