# 使用说明与来源职责

## 1. 知识库定位与唯一执行入口

本知识库用于起草、审查和修订逐点 reviewer response。它以江 TIE_2621 为唯一的 Response organization / expression 原始金标准，并以当前项目的 reviewer 原 comment、稿件、实验、结果、图表和真实修改状态决定事实与可支持的 claim。

`06_Response生成与验收流程.md` 是 **Draft、Audit、Revise 的唯一执行协议**。本文件只规定来源权限、任务范围和知识定位，不另行维护执行顺序。正式工作先确定本轮模式与授权范围，再进入 `06`；其他文件按 `06` 的稳定章节定位按需调用。

这里的“正式规则”“执行入口”和“溯源材料”职责不同：

- `03_最终知识库/01–05、07` 是 Agent 直接调用的正式规则；
- `03_最终知识库/06` 是唯一执行入口，负责把正式规则组成分层工作流；
- `03_最终知识库/08` 是候选映射和历史验证记录，不是运行时正确答案；
- `04_TIE句子级表达重建/` 是 scene、realization、candidate、validation 和 provenance 材料，用于溯源、研究及争议核查，不是第二套 workflow。

历史 KEEP/PASS、旧 handoff、旧审计或旧版本结论只能说明当时状态。它们不得覆盖当前用户明确指令、当前 primary evidence、可核查的真实 failure 或新发现的规则冲突。

## 2. 来源权限

来源只在各自权限内生效，不能互相替代。

1. **当前用户明确指令**决定本轮目标、模式、范围、阶段和特殊约束；后续明确修正优先于旧 handoff 或历史记录。
2. **当前项目 primary evidence** 决定 reviewer 实际提出的问题、事实、可支持的 claim、实验和修改是否真实存在，以及图号、公式、数值、citation 和位置等信息。
3. **作者明确确认的 response plan** 决定已经确认的 scientific mainline、concern decomposition、必要推理依赖和明确指定的主要回答顺序。作者只列出待回答事项时，不自动冻结其排列顺序。若该方案与 reviewer concern、primary evidence、数学正确性或可支持的 claim 冲突，须记录冲突并等待裁决，不能静默改写或机械执行。
4. **`Response_TIE_江_No.17-TIE-2621.pdf`** 是 Response organization / expression 的唯一原始写作金标准。它决定在项目约束之外仍有自由度的功能组织、信息推进、句子实现和专业表达；其中的漏答、错号、非地道表达或过强 claim 不因来自范例而可迁移。
5. **`03_最终知识库/00–08`** 是已经提炼和验证的正式知识层，不能覆盖 TIE 原文，也不能替当前项目材料决定事实。
6. **TIE 构建与验证材料**只用于追踪规则来源、适用边界和争议，不把单例 scene 直接升级为通则。
7. **Nature / Academic Research Suite**只可提供 evidence、claim、source、consistency、validation 和 QA 纪律，不提供或覆盖 TIE 文风及组织规律。

来源不得越权：范例不能替新稿件定义变量；作者方案不能使缺失证据成立；稿件不能证明 TIE 惯用句式；脚本或代码图注不能替正式结果；派生总结不能冒充 primary source；重复总结不增加独立证据强度。

## 3. 任务模式与范围

进入 `06` 前只需明确当前任务属于哪种模式，并锁定可处理的对象和版本：

- **Draft**：从已核验材料生成指定范围的 Response；
- **Audit**：完整发现和分类问题，不自动修改；
- **Revise**：依据已确认问题定点修订并复核受影响链条；
- **Point Fix**：Revise 的范围约束，不是另一套流程；
- **Knowledge-base Update / Repository Operation**：只处理用户授权的知识或仓库任务，不自行转入 Response 工作。

Draft、Audit、Revise 共用 `06` 的层级、判据和完成门槛，只改变在每层执行生成、检查还是定点修改。当前任务未授权的阶段不得顺带开展。

## 4. 正式知识定位

按当前单元的实际需要加载，且保留完成该单元判断所需的上层语境。

| 文件 | 正式职责 | 典型调用条件 |
|---|---|---|
| `01_TIE_Response_核心逻辑与组织.md` | Whole Response、Part、Paragraph、evidence block 的组织规律 | 规划或检查整体主线、部分职责和段落边界 |
| `02_TIE_表达_句法_语气.md` | 连续句、单句、句法、措辞、语气和节奏 | 规划或检查段内推进与语言实现 |
| `03_实验_结果图_Caption.md` | 实验、结果、图、caption 与正文协作 | 回复涉及新增实验、比较、图表或结果读取 |
| `04_证据_Claim_术语_引用.md` | evidence、claim、数学、来源、术语和引用一致性 | 核对事实、修饰关系、证据范围和可追踪性 |
| `05_错误模式与负例.md` | 已验证的错误模式和禁止路径 | 审查历史 failure 是否回流 |
| `06_Response生成与验收流程.md` | Draft、Audit、Revise 的唯一分层执行协议 | 每次正式 Response 任务 |
| `07_条件型补充规则.md` | 多义务、漏读、多 reviewer 隔离等条件规则 | 仅在触发条件成立时 |
| `08_阶段3验收与候选映射.md` | 历史候选、验证和映射记录 | 需要解释历史裁决时；不作为当前运行判定 |

当前 realization 的证据入口是 `04_TIE句子级表达重建/00_TIE_2621_sentence_realization基准.md`。其中 A1–A6 为跨场景机制，B1–B6 为情形触发机制，C1–C6 只在匹配情形下回查原 scene。A/B/C 等级约束证据强度，不提供固定 Part、段落、句数或写作模板。

## 6. 泛化与独立使用边界

- 迁移稳定功能、组织和推进，不复制 TIE 的原句、拼写错误、非地道搭配、绝对化比较、平台、参数或图号。
- `Thanks for...`、`According to your suggestion`、`For your convenience`、`To further...` 只是一种可能实现，不是强制模板。
- 当前 C1/C2 或其他单例任务的变量、指标、公式、设置、数值、figure、citation、段落形态和具体修法不进入通则。
- 已有验证边界保持有效，但新的可核查 evidence 或真实 failure 可以重开相应规则；不得用“历史已 PASS”拒绝检查。
- 只依赖本知识库时，仍须取得当前项目的原始 comment 与可检查材料。关键事实、实验状态、修改位置或 citation 不可验证时，必须显式标记缺口，不能用 TIE 风格补造完成状态。

## 7. Provenance 记法

- `TIE Rn-m, PDF p.x`：TIE PDF 的具体 reviewer 条目与物理页；
- `CK-xxx`：阶段 2 审核后的候选；
- `ESC-xxx`：阶段 2 条件型外部补充候选；
- `CI-xxx / EV-xx`：阶段 1 裁决或演变链，主要用于负例和边界；
- `supporting`：只作为兼容性、事实性或 QA 辅助，不作为 TIE 文风证据。
