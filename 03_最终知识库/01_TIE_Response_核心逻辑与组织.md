# TIE Response 核心逻辑与组织

## 1. 总体推进：先判断 situation，再安排功能块

先从 reviewer comment 判断真实 situation，再调用对应的 B1–B6。跨场景可用的是：礼貌承接后尽快进入可回答的对象、技术事实或动作（A1）；按任务复杂度安排功能块和篇幅（A2）；有图表时定位 evidence 并读出 observation（A5）；报告可核查的修改位置或摘录（A6）。这些关系不构成一条每项都必须出现的统一链。

局部 correction 通常很短；独立技术或证据任务越多，通常出现更多功能块。下一块应接续上一块留下的实际问题，而非仅按操作发生顺序罗列。location 可在摘录或证据之前，也可在其后；短答和 location 均不证明 concern 已充分覆盖。proof challenge、novelty 和完整多控制器比较的整条路径只有单例，须按 C1–C3 参考。

该路由综合 TN-01、TN-02、TN-03 和 TN-08；TN-07 只在确需结论时连接独立质量审计。主要 PDF 锚点为 R1-2（p.3–6）、R2-1 至 R2-6（p.7–10）、R3-1/2（p.11–17）、R4-3/6（p.18–21）。

## TN-01 首段实质落地

### 正确状态

`Response:` 后可以有一句简短感谢，但首段的主要信息必须尽快落到下列至少一项：

- 对 concern 的直接答案；
- 已完成的实验、比较、推导、纠正或稿件修改；
- 复杂回复即将使用的核心证据和主要结果。

TIE R1-2 先承认测量噪声的重要性，随即报告新增鲁棒性测试；R2-1 直接报告 Jacobian 表述已修正并给出摘录；R4-3 直接报告已在真实机器人上补做实验。R3-1 和 R3-2 的核心动作出现偏晚，是可识别的弱点，不应被复制。

### 下一句决策

感谢句之后问：reviewer 此刻最需要知道的是“答案是什么”还是“作者做了什么”？下一句必须给出其中之一。只有在不先定义条件就会误解答案时，才先给一个最小条件句。

### 边界

- 直接性不等于固定被动语态，也不禁止 `clarify`。
- `We wish to clarify...` 不能单独承担回答；后面必须立即出现被澄清的实质内容或修改。
- 未核验的动作不得写成已完成。

**Provenance:** CK-001；TIE R1-2、R2-1、R4-3；CI-021/022 仅作为历史反例。

## TN-02 concern 驱动的回复主干

### 正确状态

每个展开段只推进当前 concern 的一个可判断主张。段首让读者知道本段要解决什么，段中给必要理由或 evidence，段尾说明该 evidence 如何改变对 concern 的判断，或自然交给下一个未解决子问题。

对复合概念，先建立 reviewer 作判断所必需的最小框架。例如，当同一 comment 混合不同指标、比较口径或时间尺度时，先说明每个维度回答什么，再把证据分别放入相应路径。框架的作用是防止概念偷换，不是写成教程。

### 从 concern 到有序判断、Part 和 Paragraph

先顺读 reviewer 的完整论证，区分支撑质疑的论据、reviewer 据此形成的判断，以及最终要求作者回答、解释、证明、补证据或修改的事项。**独立 response obligation** 是原 comment 或明确语境要求作者分别闭合的回答事项；判断的是该请求是否完成，而不是某个技术命题能否独立判断真假。论据即使需要核验或解释，也不自动成为独立义务，应在所属回答中按需要处理，不据其数量另造 Part。只有原文或明确语境另有需要分别闭合的请求时，才单独记录。保留请求中的并列条件和选择关系，不把可替代的回答分支改成必须同时完成的任务。此处识别的是实际义务，不提供固定分类或对外提纲；完整性由 SD-01/CS-01 核查。

写作前先把 reviewer 真正要判断的问题与当前项目可核查的事实、动作和证据对齐，确定整条 Response 的直接回答，以及支撑这一回答所必需的核心判断。再依作者明确确认的回应路线和实际理解依赖安排这些判断：需要对象、条件、比较基准或证据入口的判断，应在这些信息清楚后展开；相互独立的判断则按 concern 与证据的关系自然转换。不能只按 comment 的字面次序、实验完成次序或连接词排列。若证据只支持部分回答，保留其边界，由 SD-01/CS-01 独立核查覆盖与 claim 范围。

在这条整体逻辑下，一个 **Part** 是承担同一阶段回答任务的连续内容，可以只是一段，也可以包含数段，不要求标题或编号。先说明它要使 reviewer 明白或判断什么、为何在此处出现、前一 Part 已建立什么，以及若有后一 Part，需向其交接什么；相关判断可以合并，确有不同任务时才分开。再逐个 **Paragraph** 确定本段承担的局部判断或推进动作、需要哪些理由或 evidence、与前后段怎样接续；段落数由这些实际任务及证据决定。短的局部答复不为凑层级而拆分，复杂答复也不因压缩而混淆独立判断。

**证据边界：** 这一层级规划只整理 TIE R1-2、R2-4/R2-6 中已经核对的功能接续，以及 A2/B3/B4 的任务规模与推进范围。R3-1/R3-2 的完整路径仍受 C2/C3 单例边界约束，不能从中固定 Part/Paragraph 的顺序、数量或篇幅。上述规划只用于内部生成，不作为向 reviewer 逐项宣布的提纲。

### 按 reviewer situation 选择功能块

1. **B1 局部 correction：** 指出被改对象与动作，再给可核对的替换句或位置。Figure clarification 也可采用短答，但短答是否说明具体输入/输出需另作 completeness 审计。
2. **B2 局部 equation/definition：** 修订对象 → 所问的局部技术关系或定义 → 修订式、摘录或位置。若 comment 同时指出 typo，纠错与技术解释可分成实质不同的块。
3. **B3 缺少 derivation：** 已补推导及式号对应 → 使用的前提或恒等式 → 连续中间式 → 末步所用事实或新符号。具体运算及数学真值另核。
4. **B4 新增 experiment：** 实验动作 → 具体 setup → evidence locator → observation。purpose 可以出现，但不是固定首块；稳定机制止于 observation。
5. **B5 comparison：** baseline 的已有作用或能力 → 同一比较维度上的区分点，再按需要进入技术解释或图表证据；不固定逐句先后或完整多图表路径。
6. **B6 multi-concern：** 一个 action、explanation 或 evidence block → 另一个带来新实质内容的 block。可以分点，但编号和连接词本身不构成新块；逐项完整覆盖由 SD-01/CS-01 检查。

核心证明挑战（C1）、novelty 的完整辩护（C2）、PID/MBAC 等完整多图表比较（C3）、method motivation（C4）、明确 Table 请求（C5）和定量噪声链（C6）各仅有单例，可回查原 scene，不按其篇幅、段数或全链生成。

### 下一段决策

段末判断当前句群留下什么实际需求：局部解释尚缺条件，就补条件；式链尚缺中间步，就接推导；图表只有 locator，就读 observation；存在另一个独立 concern，就切换到新的实质块。需要可核查的 manuscript location 时，可在摘录或证据前后给出。是否已经充分回答全部 concern，由独立 completeness gate 判断，不能从原文的停止位置倒推。

**Provenance:** CK-003、CK-004、CK-016；TIE R2-2、R3-1、R4-5；supporting 的原子覆盖见 SD-01/CS-01。

## TN-03 evidence block

### 定义

一个 evidence block 是服务同一子问题的一组连续证据。实验块在动作之后给出解释图表所需的具体设置，再定位图表并读出 observation（B4/A5）；局部推导块从已知关系进入中间式与末步依据（B3）；comparison 块将 baseline 的已有作用贴近区分维度（B5）。公共对象、指标和条件只需集中说明一次，每项 evidence 的独有条件和结果仍须可恢复。purpose、Figure/Table 与结论均按实际任务出现，不预设固定段数或末块。

### TIE 原文中的实际形态

- R1-2 将三个噪声强度置于同一鲁棒性测试组。公共噪声模型与公平比较条件先交代，随后集中说明各组幅值、对应 figures 和收敛现象，最后指向稿件位置。
- R2-2 将多个不等式放在同一证明链中；其完整核心证明组织属于 C1 单例，条件贴近 claim 的 A4 仍可迁移。
- R3-2 先说明 PID/MBAC 比较的理由和新增比较，再连续放置 Fig. 7–14 与 Table 1，图后集中读出 tracking error 和参数估计差异。
- R4-3 用较短 evidence block 连续交代真实机器人平台、轨迹、结果图和 observation；其后广义 robustness 结论是 source defect。

### 归并与压缩

- 相同目的和公共设置只说一次。
- 每项实验的独有条件、关键结果和实质不利比较必须保留。
- 不为每张图重启一套 purpose → setup → result → mini-conclusion。
- 不因为“已经交代公共设置”就删掉区分不同实验所需的信息。
- block 的数量由 concern—evidence 关系决定，不预设为两个或任何固定数。

### 进入和退出

进入 block 时报告当前所需的具体动作、技术前提或 baseline；purpose 仅在确有解释作用时出现。设置或前提完成后进入相应的图表或式链，locator 后要有 observation。只在确有时间或程序顺序时才用 `Next`、`Finally`。是否再写结论及其范围由 TN-07 与 SD-01 的独立审计决定，不再逐图复述。

**Provenance:** CK-005、CK-006、CK-008、CK-020；TIE R1-2、R2-2、R3-2、R4-3；CI-026/028 为拒绝路径。

## TN-07 条件型结论与 claim gate 接口（历史 ID）

### 正确状态

新 response 若确需结论，先由 SD-01 检查它能否回指直接证据，以及对象、指标、条件和范围是否匹配。TN-07 只保留非重复的结论表达检查，不要求每个 evidence block 必有结论，也不把结论出现或充分覆盖后停止描述为 TIE 原文稳定行为。

收束句不应：

- 重新枚举全部图值；
- 引入新的防御术语或新的比较口径；
- 从有限实验推出最低、普遍、保证性或跨平台结论；
- 在正面结论之后再加一轮无必要的免责声明。

如 reviewer 明确要求 limitation、风险或未完成项，必要限定属于答案本身，应保留。

### 位置与完成度

稿件位置可以先于摘录或实验段，也可以后于结果；A6 只要求可追溯。回答是否完整、结论是否越界分别由 SD-01/CS-01 的 completeness 与 evidence→claim gate 决定。

**Provenance:** CK-011、CK-012、CK-015 为历史归属；新版 realization 基准 A2/B4/B6 与独立 quality gates；TIE R1-2、R4-3 的过强实验结论仅作 source defect。

## TN-08 规模随证据变化

### 规模判定

| concern 类型 | 默认规模 | TIE 锚点 |
|---|---|---|
| 赞许、纯文字错误 | 一句或一小段 | R1-1、R1-3、R4-1、R4-2a |
| 局部定义、公式或图示不清 | 一段回答，必要时附修订摘录或关键式 | R2-1、R2-3 至 R2-6、R4-2b |
| 核心证明、原创性、方法动机 | 篇幅随该 comment 的实际技术任务变化；完整路径仅作 C1/C2/C4 单例参考 | R2-2、R3-1、R4-5 |
| 新实验；含多个比较任务的 comment | 独立证据任务增多时通常有更多功能块；完整多图表比较路径仅作 C3 参考 | R1-2、R3-2、R4-3、R4-6 |

长度、段数和图量只由 concern 与可核验证据决定。简单问题不为模仿 TIE 外观而扩写；复杂问题不为追求“简洁”而裁掉必要条件或 evidence。图多不等于回答充分，字少也不等于 TIE 风格。

**Provenance:** CK-016、CK-020；TIE 全篇长短条目对照。

## 2. 主组织快速审计

起草完成后，只沿阅读路径问六个问题：

1. 首段是否已经给出答案、动作或核心 evidence？
2. 每一段是否只推进一个当前判断？
3. 每个 evidence block 的目的和边界是否可见？
4. 公共信息是否集中，独有 evidence 是否仍完整？
5. 有 Figure/Table locator 时，是否读出了与 concern 有关的 observation？
6. manuscript location 或摘录是否可查，且没有被固定为尾句？

这六项检查 TIE-native 的组织与读取；claim 范围、concern 完整度和停止充分性由 `04`、`06` 另审，词句实现由 `02` 审查。
