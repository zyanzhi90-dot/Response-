# 冲突与演变链

> 本文件只记录存在前后冲突、后续纠正、TIE 重核撤回、`SUPERSEDED` 或 Agent 过度泛化的项目。顺序采用“较早状态 → 触发复核 → primary evidence / 用户裁决 → 当前状态”。A2 从 handoff 继承的内容不算独立确认。

## EV-01：`We wish to clarify` / `The point we wish to clarify`

- 较早状态：Agent 将 `We wish to clarify ...` 视为自然且接近 TIE 的开场，并曾把 `The point we wish to clarify ...` 当作 TIE 原句。
- 触发复核：用户明确指出 TIE 范例没有这种惯用开场。
- 证据回查：TIE PDF 未发现该语言指纹；`The point ...` 来自总结文件标注的“项目增强”，不是原文。
- 因果裁决：derived summary 不能冒充 primary source。当前回复应直接进入研究目标、已完成动作或证据。
- 当前状态：CI-021 `REJECTED`。
- 边界：否决的是把这些表达当作 TIE 语言指纹或默认开场，并非宣称 `clarify` 在任何语境都绝对禁用。

## EV-02：`We do not claim ...` 的状态变化

- A1 较早记录：该句在早期版本中出现；用户只提出“是否过强、需重新判断”。A1 自审纠正了先前误标，将其保留为 `UNRESOLVED`，因为当时没有最终批准或否决。
- A2 后续：版本改为正面界定真实计算目标、直接报告 comparisons 和有限证据；用户对内容、逻辑和表达做了整体验收。A2 的错误历史把直接对抗式 `We do not claim ...` 作为当前开场方向排除。
- A3 再确认：`do not claim` 被列为暴露更大风格问题的实例；默认的 meta/negative opening 被否决，结尾的重复免责声明也被删除。
- 当前裁决：A1 unresolved → later resolved by A2/A3。作为当前项目默认/TIE 式开场，CI-022 为 `REJECTED`。
- 仍未解决的相邻问题：A1 候选 `rather than ...` 的精确字符串没有被 A2/A3 保真记录为已批准，故 CI-056 仍为 `UNRESOLVED`。

## EV-03：一般 academic-writing 偏好 vs TIE 原文

- 较早模式：Agent 多次以“更规范、更专业、更完整”为由提出新增修改。
- 用户纠正：要求回到 TIE 原文，而不是用一般 phrasebook 填空。
- TIE 重核结果：部分建议并非 TIE 特征；某些甚至属于总结者补写、偶然句型或模型自建规范。
- 当前裁决：primary TIE evidence 决定“范例实际如何写”；一般 academic preference 不能自动覆盖。CI-023 `REJECTED`。
- 可保留机制：迁移论证动作、信息密度和证据位置，而非机械句式；见 CI-018。

## EV-04：具体反馈是局部替换清单，还是完整标准校准

- 早期错误：Agent 只改用户点名的五处/八处表达，随后过早声称已达到 TIE 水平。
- 用户纠正：点名短语只是“扫一眼能发现”的样本；每发现一类问题要回查全文同类表达。
- 后续边界：全面审计不等于全面重写；已正确且已通过内容不得继续泛化润色。
- 当前裁决：CI-002 与 CI-019 为 `GENERALIZABLE_CANDIDATE`；“只做点状替换”和“通过后继续无边界润色”均保留为真实负例。

## EV-05：`Next / Finally / For the original task`

- 较早文本：用 `Next`、`Finally`、`For the original task`、`For the same task` 串联四组实验。
- 用户反馈：这些表达只说明操作顺序，没有解释该证据回答 reviewer 的什么判断。
- TIE 回查：TIE 的相关段落用目的—设置—结果—有限结论推进；可见 `To further show/verify` 的功能，但并非固定模板。
- 当前裁决：CI-024 `REJECTED`；purpose-led entry 为 CI-008 `GENERALIZABLE_CANDIDATE`。

## EV-06：purpose sentence 的作用与模板化风险

- A1 状态：目的性进入的功能得到支持，但多段重复 `To further evaluate/examine/verify` 的密度仍未最终验收。
- A2/A3 后续：用户明确反对 Case 1、Case 2、`W_x`、`S_e(t)` 各自重启同一套模板；相关内容改为 evidence blocks。
- 当前裁决：A1 unresolved → later resolved by A2/A3。保留“说明证据目的”的功能，否决固定句型重复。CI-008 为候选；CI-026 `REJECTED`。

## EV-07：逐图 mini-response → evidence blocks

- 较早结构：每张图单独写 purpose → setup → result → mini-conclusion，最后再整体总结。
- 用户反馈：TIE 的共同逻辑不是“每张图各自写一套完整 response”。
- TIE 重核：R1-2、R3-2、R4-3 均支持相关 tests/comparisons 作为连续证据组进入，图组附近集中读结果，一次有限收束。
- 当前应用：Cases 1/2 为一个 block，`W_x/S_e(t)` 为另一个 block。
- 当前裁决：逐图 mini-response 为 CI-028 `REJECTED`；evidence-block 机制 CI-005 为候选；“恰好两个 block”CI-040 为 `CASE_SPECIFIC`。

## EV-08：“公共设置集中”是否等于“只许一次设置说明”

- 初次压缩：A2 将共同目的与公共设置集中交代。
- 用户二次校准：不要把它理解为整个 Section 2 只能出现一次设置；目标是删除重复论证，不是删除必要证据。
- 复核结果：Case-specific `C`、全部 `J_10` 数值、4.75/4.65 ms、`W_x/W_f` 和三个 `S_e(t)` 设置仍保留。
- 当前裁决：共同信息集中与独有证据保留同时成立，CI-006 为候选；“为了简洁删必要证据”为真实拒绝路径。

## EV-09：caption 自足、正文高密度与 citation 重复

- 稳定部分：caption 保留方法/条件/指标/面板和参考线，正文只读 reviewer 判断所需的关键现象。
- Agent 过度泛化：曾提出 caption 中每次出现 `IL-SOGP` 都必须重复 `[10]`，并将未重复判为失败。
- 用户追问与 TIE 重核：TIE 正文首次介绍比较方法时给引用，后续 caption/图不必为形式统一机械重复。
- 当前裁决：caption/正文功能分工 CI-009 为候选；“所有 caption 必须重复 citation”CI-027 `REJECTED`；当前 captions 不重复为 CI-043 `CASE_SPECIFIC`。
- 注意：当前图内 `IL-SOGP [10]` 是独立的用户图形裁决，不能反向证明 caption 通则。

## EV-10：模糊 `panels (c)` → 具体 Fig. references

- 较早文本：两个 figures 并列时只写 `panels (c)` / `Panels (d)`。
- 用户反馈：需要直接点明具体图号，避免 reviewer 回读和错配。
- TIE 重核：多图讨论中存在直接点明具体 Fig. 的实际做法。
- 当前修改：使用两张 figures 的具体 `(c)` / `(d)` references。
- 当前裁决：当前句子 CI-041 `CASE_SPECIFIC`；降低歧义与回读成本 CI-010 为候选；“所有结果句必须完整枚举图号”未被建立为规则。

## EV-11：`real-time-feasibility criterion` 的微调

- 较早文本：`real-time-feasibility criterion`。
- 用户定点修改：改为 `real-time feasibility criterion`。
- 后续复核：这是当前句子的语言准确性处理，不能包装成 TIE 特有标点规则。
- 当前裁决：CI-042 `CASE_SPECIFIC`；作为普遍 TIE 规则的说法被拒绝。

## EV-12：computation-time 指标名称和符号

- handoff/较早文本：`maximum total computation time per step`；图形阶段一度采用 `T_on^max`。
- 用户正式裁决：评价对象应为每个控制步的在线计算，正式名称改为 `maximum online computation time per control step`，符号统一为 `t_comp^max`，判据为 `t_comp^max < Δt`。
- 一致性检查：A2 在 Comment 1 正文与必要 captions 清除旧名称；A3 再次记录最终语义。
- 当前裁决：旧名称 CI-032、旧符号 CI-033 均为 `SUPERSEDED`；当前具体名称/符号 CI-039 为 `CASE_SPECIFIC`；“首次定义清楚、后续稳定”CI-014 为候选。

## EV-13：`b:c` → `W_x:W_f`

- 较早路径：Agent 从图文件名、脚本或外部案例把 `b:c` 当作正式权重表示。
- 用户纠正：应根据当前稿件，而稿件定义 `S=[W_x 0 W_f]`。
- 事实回查：JAS 不负责定义本稿权重变量；当前稿件是符号 primary source。
- 当前裁决：CI-034 `SUPERSEDED`；当前图/正文使用 `W_x:W_f`，作为项目事实进入 CI-046/CI-050。

## EV-14：`S_{e,max}` → `S_e(t)`

- 较早路径：从“峰值”概念另造 `S_{e,max}`。
- 用户纠正与稿件回查：本稿正式使用 `S_e(t)`，图中按当前裁决使用 `I` 而非 `I_2`。
- 当前裁决：CI-035 `SUPERSEDED`；当前符号属于 CI-046/CI-050。

## EV-15：CRBFNN 扩写方向

- Agent 扩写：20 vs 729 neurons、network size、tracking error 和 runtime 说明。

## EV-16：JAS 设置密度

- A1 状态：保留 Panda、uneven surface、trajectory/contact environment、`C/α` 到什么程度仍未定；“只写 Cases 1 and 2 必然不足”也被自审核降为未决。

- 当前裁决：A1 unresolved → later resolved by A2/A3。当前分配为 CI-040/CI-049 `CASE_SPECIFIC`/`SOURCE_FACT_ONLY`；“最小充分设置”机制进入 CI-006。

## EV-17：claim boundary 从 JAS Cases 扩展到 `W_x/S_e(t)` variations

- handoff/A1 较窄状态：明确的 real-time feasibility 主要收束在新增 JAS Cases；A1 对权重/刚度图能否用 20 ms 扩展结论仍未决。
- A2 后续：加入并核验 `W_x/S_e(t)` computation-time 图；用户接受结论覆盖 two tested tasks 与 reported variations。
- 约束未变：不得推广到未测试任务、平台、采样周期或 universal guarantee；proposed timing 一般高于 IL-SOGP 必须保留。
- 当前裁决：A1 unresolved / earlier narrow boundary → later resolved and superseded by A2/A3。CI-037 `SUPERSEDED`，现行 CI-047 `CASE_SPECIFIC`，抽象 claim discipline 为 CI-011。

## EV-18：不利结果是否保留

- 潜在错误方向：为维护“计算优势”而弱化 proposed method 相对 IL-SOGP 更慢的结果。
- 正式图事实：Cases 和 variations 中 proposed computation time 可以高于 IL-SOGP，但低于相应 control period。
- 用户裁决：必须如实保留；本回复证明的是有限实时可行性，不是最低计算成本。
- 当前裁决：隐藏/过度包装 CI-030 `REJECTED`；保留不利结果 CI-012 为候选；具体结果 CI-051 为 `SOURCE_FACT_ONLY`。

## EV-19：何时可以宣布“达到 TIE 水平”

- A1 早期错误：只修少数显性短语后即宣布达到 TIE 水平。
- 用户纠正：必须逐句、逐词、逐段并按整体逻辑、图文关系、术语和 claim 边界验收。
- A2 后续：用户明确判断某一版本“整体已经通过内容、逻辑和表达验收”，随后只允许定点修改。
- 当前裁决：过早完成声明被拒绝；证据化整体验收与通过后停止泛化润色成为 CI-019 候选。项目层面的具体通过状态见 CI-048。
- 文件状态边界：A2 后续文本修改未重新编译，故“写作验收通过”不能等同于“最新版排版/提交状态完成”；CI-054 仍未决。

## EV-20：代码图注 vs 正式 response caption

- 较早歧义：`不要看图注` 容易被理解为所有 caption 都不可用。
- 用户澄清：不作为上游证据的是代码生成的图注、脚本、运行说明；审稿人会看的正式 response caption 必须准确、自足。
- 来源职责：最终正式图支撑数值/曲线关系，稿件/JAS支撑定义和设置，response caption 是核实后写给 reviewer 的输出。
- 当前裁决：来源替代错误归入 CI-029 `REJECTED`；caption/正文分工 CI-009 为候选；当前正式图事实 CI-051 为 `SOURCE_FACT_ONLY`。
