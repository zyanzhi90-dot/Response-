# 外部补充候选

> 本文件只保留阶段 1 的 CK-001～CK-020 尚未覆盖、且直接服务 reviewer response 的外部补充候选。它们仍是候选，不是最终知识库规则。

## 数量

共 3 条 `EXTERNAL_SUPPLEMENT_CANDIDATE`。

## ESC-001：复合 comment 的原子化覆盖与 no-silent-drop

- **ID:** ESC-001
- **Function:** 在起草前忠实保留 reviewer comment，并把一个复合 comment 拆成可追踪的原子 concern/commitment，确保每一项都被回答、明确拒绝或保持可见未决。
- **External source:** NR-TAXONOMY、NR-WORKFLOW、NR-QA；ARS-REVISION、ARS-REBUTTAL。
- **External evidence:** Nature 要求识别 compound concern、逐项映射 action/evidence 并做 completeness check；ARS 要求 preserve reviewer intent、atomic commitments、no silent drops，并把未解决 gap 显式保留。
- **与 TIE 的兼容性:** 与 TIE point-by-point、直接进入动作和证据的实际组织相容；它规定的是回应前的覆盖机制，不替换 TIE 的句法、段落节奏或证据表达。
- **为什么现有 CK 没覆盖:** CK-003 解决“用什么证据回答 concern”，但没有完整规定如何从原始 reviewer comment 建立不漏项的原子 concern inventory；CK-019 是完成门槛，不等于 comment 解析协议。
- **Boundary:** 只拆分 reviewer 实际表达的独立要求或判断点，不把一句话过度解析成 Agent 自创任务；外部-facing response 是否分段可按可读性决定，但内部映射必须可追踪。
- **Overgeneralization risk:** 容易把“原子化”误执行成机械逐句回复、段落碎片化，或为每个修饰语制造一项工作。
- **推荐状态:** `EXTERNAL_SUPPLEMENT_CANDIDATE`

## ESC-002：把 reviewer 的误解或漏读视为清晰度信号

- **ID:** ESC-002
- **Function:** 当 reviewer 漏看已有信息或提出事实性误解时，先直接回答科学问题，再改善措辞、位置、signposting、legend 或 cross-reference，而不是责备 reviewer“没有看到”。
- **External source:** NR-STANCE、NR-WORKFLOW、NR-DIFFICULT、NR-TONE。
- **External evidence:** Nature 的 difficult-case 原则明确要求不指责 reviewer、不以“already stated”结束回应，并把漏读视为原 presentation 不够清晰或可见的信号。
- **与 TIE 的兼容性:** 与 TIE 的 action-forward、evidence-linked、非元话语式推进相容；它只补充一种常见 reviewer 情形的处理机制。
- **为什么现有 CK 没覆盖:** CK-001 关注开头直接性，CK-010 关注指代与图号歧义，但都没有规定“已有信息被漏读”时如何分配责任并形成 revision action。
- **Boundary:** 只有在 primary source 证明确有相关内容时才能称为已有信息；若 reviewer concern 实质上仍未被回答，不能用“提高可见性”代替新增分析、证据或 claim 修正。
- **Overgeneralization risk:** 容易把所有批评都解释为 reviewer 漏读，从而逃避真实缺口；也可能为已清晰内容做无止境重写。
- **推荐状态:** `EXTERNAL_SUPPLEMENT_CANDIDATE`

## ESC-003：互盲 reviewer 的隔离与独立完整回应

- **ID:** ESC-003
- **Function:** 在 reviewer 互盲的修订包中，让每位 reviewer 的回复独立完整，不泄露其他 reviewer 的 comment、编号、建议或作者对其的答复。
- **External source:** NR-ENTRY、NR-STRUCTURE、NR-QA、NR-DIFFICULT。
- **External evidence:** Nature response Skill 明确要求 reviewer-specific isolation；对重复或冲突 concern，只能在 internal/editor master 中关联，reviewer-facing response 需分别给出完整且一致的解释。
- **与 TIE 的兼容性:** 与 TIE 的 point-by-point 独立回应结构兼容；该原则管理跨 reviewer 信息边界，不改变 TIE 的 response logic 或语言基准。
- **为什么现有 CK 没覆盖:** CK-001～CK-020 均处理单条 response 的论证、证据、图文和 QA，没有处理多个互盲 reviewer 之间的信息泄漏与跨引用。
- **Boundary:** 只在 reports/作者回复互相不可见或期刊要求隔离时适用；若 editor 明确要求综合答复或 reviewer reports 公开共享，应遵从 journal/editor instructions。内部 master 可以记录重复与冲突，但不得直接复制到 reviewer-facing 文本。
- **Overgeneralization risk:** 容易把“隔离”误解为不同 reviewer 必须得到不同科学结论，或阻止作者在稿件中实施一个统一、全局一致的修改。
- **推荐状态:** `EXTERNAL_SUPPLEMENT_CANDIDATE`

## 未新增的相邻外部原则

- “action / work status / package readiness 分离”已作为 CK-019 的重要边界，不另建重复候选。
- “claim 的部分支持不能当作完全支持”已由 CK-003、CK-011、CK-012 覆盖。
- “超范围实验、统计、伦理、appeal”等属于特定情形工作流；现有 TIE/三源和本轮 20 条 CK 不足以把它们抽成同层级通用候选，故未新增。
