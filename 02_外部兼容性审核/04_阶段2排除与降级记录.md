## 2. 未采用的 Nature 相关内容

| 外部内容 | 未采用原因 | 处理位置 |
|---|---|---|
| Nature 示例中的固定致谢、同意、不同意或 revision phrase | 属于 phrasebank / house-style illustration，不能替换 TIE 的实际写法，也不能推出统一开场 | 明确排除；CK-001、CK-015 只保留功能层 |
| 固定使用被动语态、固定标题、固定 response block 版式 | 外部资料没有把这些设为跨项目硬规则；不同 comment 的回应动作不同 | 明确排除；CK-001/CK-020 边界 |
| Nature 的标点、拼写或其他一般 language preference | 一般 academic-writing 偏好不能覆盖 TIE benchmark；与 reviewer-response 机制无直接关系 | 明确排除 |
| 每条修改都必须给稳定页码/行号 | 定位必须可核查，但页码会随版本变化；可按文件格式使用 section、paragraph、figure、line 或 placeholder | 不形成独立候选；纳入 CK-007、CK-010、CK-019 边界 |
| caption 必须重复所有 citation 或正文结果 | Nature main-text discipline 强调功能分工而非机械重复；阶段 1 已把 caption citation 降为项目/期刊依赖 | 明确排除；CK-009/CK-017 边界 |
| 为回应 reviewer 而把所有解释都追加进 main text | 会造成 revision accretion，并可能破坏稿件主线；应按功能替换、压缩或路由至 caption/Methods/SI | 明确排除；CK-006/CK-016 对照 |
| 超范围实验的固定拒绝模板 | 是特定 difficult case 的策略，不是所有 response 的通用表达；当前 TIE/三源没有足够同类证据做兼容性细化 | 本阶段不新增候选 |
| 统计、伦理、合规 concern 一律按同一 blocking 文本处理 | 仅在相应 concern 出现且事实缺失时适用，属于专门工作流 | 本阶段不新增候选 |
| appeal-like case 的写法 | appeal 不等于 ordinary revision response，超出本项目当前候选层 | 排除 |

## 3. 未采用的 Academic Research Suite 内容

| 外部内容 | 未采用原因 | 处理位置 |
|---|---|---|
| 固定数量的 evidence streams、量化 argument score 或固定 rubric threshold | 来源模块面向论文论证/内部工作流，不是 reviewer response 的跨项目规则 | 明确排除；不改变 CK-003/CK-011 |
| 所有 scientific claim 都按统一 citation 规则处理 | response 中部分 claim 由本项目实验、稿件或正式图支撑，不是外部 citation 问题 | 明确排除；CK-013/CK-017 保留来源职责 |
| DOI 完整率、自引比例、参考文献格式等 paper-level 指标 | 属于 citation compliance 或投稿格式，不决定回应机制 | 明确排除 |
| 把 style profile 当作强制模板 | ARS 自身把 style calibration 定义为软约束，且其优先级低于学科/期刊要求；本项目还须服从 TIE benchmark | 明确排除；CK-018 补边界 |
| 将 `ars-rebuttal-audit` 的通过视为 ready-to-submit 认证 | ARS 明确该 audit 只给 advisory coverage/tone/evidence-risk，不验证稿件修改是否真实完成 | 明确否决；纳入 CK-019 边界 |
| ARS 的整套 research/paper/pipeline workflow | 本轮不是研究执行、论文生成、文献检索或 reviewer simulation | 未读取无关模块，不形成候选 |
